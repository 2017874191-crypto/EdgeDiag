1. 暂态 SQLite 争用不能悄悄永久耗尽 worker；持续失败必须有限重试、停止并显式不就绪。

## AUD-001：有限重试和就绪状态

DiagnosticJobs 集中包装数据库领取与完成写入。仅 SQLITE_BUSY / SQLITE_LOCKED（及对应无错误码的锁争用文本）最多尝试 5 次，间隔 50/100/200/400ms。不可重试错误直接停止该 worker。取消会向上传播，退避期间也可及时关闭。

完成写入的重试只重新写结果，不重新执行 Runtime。重试耗尽后，未完成任务可能保留 running，服务重启按照已有只读恢复策略处理；模型可能跨重启再次计费，不宣称 exactly-once。

/health 现在是就绪检查：全部预期 worker 存活且没有数据库错误才为 200，否则 503，并返回实际/预期 worker 数和脱敏错误类别。它不代表 MQTT、模型或设备整体健康。持续故障后需操作人员修复依赖并重启，未加无限监督重启。

代价：SQLite 同步调用仍可能被 busy_timeout=5s 阻塞；5 次争用最多约 25.75s（不含其他负载），不是 HTTP 延迟 SLA。下一阶段若要保证事件循环响应时间，应评估独立连接/执行线程与取消所有权，而不能简单把共享连接扔进线程池。

## AUD-002：未来时间隔离与旧库迁移

信任服务端时钟。设备 timestamp_ms 超过检查时刻 60 秒则：

- 原载荷按原去重键保存，返回 accepted=true / reason=clock_quarantined。
- 不更新设备水位，不参与持续窗口、默认历史或新诊断快照。
- 记录 clock_valid 和 clock_checked_ms；GET /v1/devices/{id}/quarantine 可查看原载荷、检查时间与策略阈值。
- 重复载荷依然去重；时间后来追上也不自动重新放行，避免同一消息改变既有判定。

数据库迁移为加列，保留所有原载荷、历史 Incident 和已完成报告；旧的未来记录被标记并重建设备水位。重复启动不会抹掉隔离的检查时间，也不会自动解除隔离。不凭空补造旧样本的接收时间。

取舍：

- 60 秒是演示默认容忍度，不是经过硬件标定的阈值。
- 容忍范围内的偏快时间仍可能使当前数据延迟处理最多约 60 秒。
- 允许过去时间数据用于现有历史回放；这不等于完整的新鲜度认证。生产直播/回放隔离、设备时间回退、服务端时钟回退和 boot 认证仍未实现。
- 不按新 boot 简单清空水位，旧 boot 的迟到消息不能借清零重写当前状态。
- 旧的已完成诊断不被重算或删除；若依赖过期/错误时钟，应人工复核。
- 迁移会扫描历史表，数据保留和大库迁移成本仍需后续容量实验。

## AUD-003：最小版本门禁

共享 agent/contracts.py 的 WORKFLOW_VERSION，由队列写入、worker 门禁和 Runtime 记录共同使用。当前仅支持 diagnose-v2。无版本、旧 v1 或未知版本一律任务 failed / unsupported_workflow_version，在 Runtime 前拒绝。

工作流版本升级的原因包含规则路径证据/Trace 变化。旧排队 v1 任务不会静默套用 v2；已完成 Trace 仍可查询。显式请求 key 的指纹绑定版本，跨版本复用同 key 可能返回 409，需用新 key 明确发起新诊断。这是失败关闭的迁移取舍，不是假装支持任意旧版本。

## 简化：规则模式减少一次查询

规则模式工具调用由 4 次减为 3 次：Incident、设备快照、温度统计。模型模式仍有第 4 次手册检索，引用编号/工具往返测试继续覆盖。未删除模型模式 RAG。

新负对照显示规则模式完整路径与去掉可选手册分支均为 3 次调用且摘要相同；原始基线 4→3 的证据保留在旧结果中。没有据此宣称真实诊断质量提高或手册对模型无用。
